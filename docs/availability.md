# Media availability

The entry editor looks up movie and TV availability through TMDB/JustWatch and game website links through IGDB. Hovering or focusing a poster reveals platform icons; lookups begin only after interaction to conserve the shared quota. TMDB does not provide direct streaming title URLs, so supported streaming icons open a clearly labelled provider search until the user adds a matching personal link. Unsupported providers offer the link editor instead. IGDB storefront links describe listed websites, not real-time regional stock or pricing. Users can choose another title match and add their own web links; these are saved with the entry and included in JSON backups. Country is a two-letter code, stored on the current device. Browser session cache entries expire after six hours.

The lookup function uses `TMDB_API_KEY`, `TWITCH_CLIENT_ID`, and `TWITCH_CLIENT_SECRET` only on the server. It supports anonymous browsing using the publishable key, with a global database budget (120 calls per minute) and a per-instance guard. The budget RPC is deliberately callable by anonymous users but exposes no entries and does not require the service-role key. Its global limit means any client can exhaust the shared budget for a minute; a dedicated per-client gateway limit and monitoring are recommended before broad public use. If the budget service fails, lookups fail closed; manual links remain usable.

## Deployment checklist

1. Confirm no existing `public.stillroom_availability_budget` table or `public.stillroom_take_availability_budget()` function belongs to another feature. Review and apply `supabase/availability-rate-limit.sql` to the intended project. Verify that `anon` and `authenticated` cannot read or update the table and that the RPC returns true, then false after the limit. The migration must be verified against PostgreSQL before production use.
2. Deploy `supabase/functions/media-availability/index.ts` with the `verify_jwt = false` setting in `supabase/config.toml`. The endpoint uses the database budget and an origin allowlist; an origin header is not an authentication mechanism. Keep the three provider secrets in Edge Function secrets, never in the repository or frontend.
3. Exercise known movie, TV, and game titles; an ambiguous remake; an unsupported region; a failed upstream; and a manually entered link. Verify attribution, retry, and links on desktop and mobile. Only then publish the frontend.

The quota migration was tested inside a rolled-back transaction (120 allowed, the 121st denied, anonymous table read/update denied) and deployed to the Stillroom project. The function was deployed and checked with real movie and game lookups and a TV title search. Automated service tests use mocked upstreams. The approved TMDB logo is loaded from TMDB; the application requires a non-commercial TMDB license unless a separate commercial arrangement is obtained. The frontend changes in this checkout still require publication separately.

## Proposed Watchmode changes (not deployed)

The local candidate requires a Supabase account session for Watchmode link lookups; signing in does not enable cloud synchronization or move local entries. The Edge Function verifies the bearer token with Supabase Auth and calls a database guard using that user's token. The guard allows at most 50 two-credit requests per account and 500 globally per rolling 31 days. Per-account limits do not prevent multiple-account abuse, and the budget cannot account for calls made by other applications using the same Watchmode key. Browser and function-instance caches are temporary and isolated. Verify deployed grants, account enrollment and the external provider quota before release. See `docs/watchmode-release-checklist.md`.
