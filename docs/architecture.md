# Architecture and data

## UI composition
`src/main.tsx` owns routing-by-state (home, library, notes, profile, settings), the entry page shell and the side-pane stack. `src/EntryPane.tsx` is the single entry editor, mounted both full-page and inside a stacked pane; it autosaves (700 ms debounce plus blur flush) and renders the hero, contextual tracking controls and notes gallery. `src/SidePanes.tsx` stacks entry/note panes with a shared width from `--entry-width`, text-only tabs when multiple panes are open, and capped peeks on the right, away from the resize divider. `src/NotesMenu.tsx` is a browse-only notes gallery. Left-click opens the existing dedicated editor and hides the entry; closing restores the entry and its scroll position. The card context menu opens a note in the separate right-pane workspace instead, beside the entry. Mobile uses a full-screen editor. Notes autosave in both presentations; closing a right-pane note flushes its draft before removing the pane. `src/AvailabilityPanel.tsx` handles provider links and renders hero pills only for verified direct destinations. Entry-page and pane styling lives in `src/panes.css`, scoped under `.entry-screen` and `.side-pane`; the current handoff is `docs/handoff-2026-11-16.md`.

Library entry left-click always opens the entry in the main area, whether or not a right pane exists. The entry context menu opens a separate right pane explicitly. Each right pane has a high-contrast 44px close control; closing the last right pane restores the main area to full width.

## Decisions
React, TypeScript and Vite form a browser-first app. IndexedDB is the local source of truth, with explicit migrations and account-partitioned caches and outbox. An account is not required for local library use. The candidate requires sign-in for direct platform-link lookups; sign-in does not itself enable sync or move existing entries. Account sync remains disabled until its independent release gates pass. Browser storage can be cleared or evicted; encourage backups. Offline use after load does not guarantee first load or remote artwork availability.

## Model and portability
Entries retain their app-generated UUID, media type, lifecycle status, notes, progress, tags, optional 1.0–5.0 rating in 0.1 increments, cover URL and optional cover position. An optional confirmed provider match retains the external ID and query; personal links remain durable. Source identity changes must not replace the entry UUID or detach notes.

IndexedDB schema v4 adds a local Wishlist store alongside the media and account stores. The combined JSON backup uses version 3, includes embedded Wishlist images, and restores the media library and Wishlist in one transaction. Versions 1 and 2 remain readable and restore only the media library. Remote artwork is represented by URL. See [Wishlist storage and backup decisions](wishlist.md#storage-and-backup-decisions-per-64). Older clients reject decimal ratings or omit new fields in sync payloads, so do not enable sync until a mixed-version safety strategy is tested.

## Provider strategy
TMDB supplies movie and TV matches; IGDB supplies game matches and some store URLs. Watchmode supplies streaming-link candidates associated with confirmed TMDB IDs. The owner accepts its title association after region, official-domain and title-route checks, with the risk of stale or wrong upstream data. The current candidate supports Netflix and Apple TV streaming pages and Steam game pages; other providers stay hidden. Metadata and link fetching may need internet. Provider secrets remain server-side; provider terms, attribution, caching limits and release checks apply.

Watchmode lookups require a verified account session. The per-account and global rolling credit guards and updated function are deployed; caching behavior, limitations and rollback are in `watchmode-release-checklist.md`. Protect local data and keep account sync optional.
