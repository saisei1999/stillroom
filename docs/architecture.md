# Architecture and data

## Decisions
React + TypeScript + Vite, browser-first responsive app. IndexedDB is the intended local source of truth (use a small maintained wrapper if useful), with transactional item and blob writes, migrations and explicit save failures. Browser storage can be evicted or cleared: request persistent storage where supported and encourage verified exports. A service worker/app shell is a later milestone; IndexedDB alone does not make first load or assets available offline. No account, server or mandatory subscription. Shadcn/ui and Motion are optional additions when their actual value is established.

## Model (versioned)
Item: UUID, title, mediaType (game, movie, tv, anime, manga, book, music), status (planned, in_progress, completed, paused, dropped), optional rating (0–5 in 0.5 steps), progress {current, total?, unit?}, review Markdown, tags[], collectionIds[], cover reference, source references [{provider,id,url?}], user-edited metadata, createdAt, updatedAt. Store null/unknown distinctly from zero. Collections: UUID, name, description?, timestamps. Assets: UUID, MIME, bytes, provenance, rights/attribution metadata. Stable IDs, referential integrity and migration versions are essential.

## Portability
JSON backup is a versioned portable envelope with all fields and asset bytes, integrity checks and creation date. Validate structure, size and version before staging; offer merge or explicit replace and keep existing data on failure. Define conflicts and ID policy in implementation before release. Markdown export uses one UTF-8 file per item with escaped YAML front matter, review body and stable ID; include local assets, deterministic collision-safe filenames and a manifest. JSON is the lossless restore format. Markdown import and Obsidian sync are future work. Do not assume remote provider artwork can legally be redistributed; preserve references and export only images when permitted, with explicit fallbacks and disclosure.

## Provider strategy and release gates
Adapters normalize search/results/cover candidates, retain provider IDs and attribution, debounce, cancel stale requests, cache conservatively, handle rate limits, and never overwrite user changes. Manual entry must remain available. Open Library is a candidate for books; covers via IDs have documented rate limits. TMDB is a candidate for movies/TV: its free API is noncommercial and requires attribution; commercial use requires separate terms. IGDB is a game candidate but credentials/auth, browser CORS and terms must be evaluated before adoption; never embed client secrets. MusicBrainz and Cover Art Archive are candidates for music; obey identification/rate policies. Anime/manga provider and game solution remain open pending licensing, CORS, rate and credential checks. Cover availability, caching/export rights, terms and attribution are release gates for each adapter. A server proxy would introduce hosting costs and weaken the no-service assumption; decide explicitly before adding one.
