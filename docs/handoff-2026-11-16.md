  (`.entry-screen`, `.entry-screen-bar`), side-pane state and the width resizer.

## Behaviour decisions a new session must keep

- The entry is a **page**, not a pane: no `ENTRY` bar, no card frame, no footer. `← Library` and `×`
  float over the artwork; a `⋯` bubble holds `Delete entry`.
- **Autosave, no confirm buttons.** `EntryPane` saves 700 ms after a change and flushes on blur; the
  `Save`/`Saved` footer was removed deliberately (reported as "this section has gotta go").
- **Star leads the title** in one flex row and flips the existing Focus tag.
- **Notes are browse-only.** Clicking a card opens the existing right-side note editor; inline expansion
  was built and explicitly rejected.
- **Properties dock** is absolute over the hero so collapsing never reflows the page; it is a quiet
  hairline list, not six nested cards. Mobile still stacks it under the hero — a bottom sheet is an open
  question, not a done deal.
- **Artwork framing:** `object-fit: contain` over a blurred copy of the same art. Portrait sources stay
  uncut; cover-cropping small posters turned them to mush.
- Every navigation action clears the open entry (`leaveTo` / `selectView`), or Library appears dead.
- Entry page is dark in both themes; the parent canvas is painted to match so no strip shows under the
  notes.

## Verification recipe

```bash
npm test
node node_modules/typescript/bin/tsc --noEmit
GITHUB_ACTIONS=true node node_modules/vite/bin/vite.js build --outDir "$SCRATCH/build"
```

Preview with the dev server on `http://127.0.0.1:5183/`. Two traps cost time in the last session:

1. Editing a module from a shell command can leave Vite serving a stale transform (blank `#root`,
   `does not provide an export named …`). Touch the file and reload; if it persists, start a second
   server on another port **with a pty**, because restarting the owner's server kills their annotated
   preview.
2. External artwork hosts are often blocked in the harness. To judge framing, inject a local canvas
   data-URI into the `.entry-art-hero img` and `.hero-blur` background and say so in the report.

Never clear IndexedDB or site data to fix a layout problem — it is the owner's library. Seed demo
records through the app's own Add form inside the same browser call that captures the screenshot.

## Follow-up owner decisions (same day; supersede earlier layout details)

- The Properties dock has been removed. Type, status, decimal rating and progress are contextual controls under the title, with local outline icons and no chevrons. Tags, artwork and metadata correction are in entry options; artwork opens beneath the upper-right menu.
- The entry now follows the app's light/dark theme. The Notes island is 80% of the page width on desktop, opaque in both themes, and grows naturally without an internal gallery scrollbar.
- **Left-click on a note hides the entry and opens the dedicated editor.** Closing returns focus to the card and restores page scroll. This explicitly supersedes the earlier requirement to keep the entry visible on ordinary note opening.
- **Right-click → Open in right pane** uses the separate side-pane workspace. The entry and note sit beside each other; there is no overlapping note overlay. Shift+F10 opens the same card menu.
- The right-pane stack now has a keyboard-accessible, text-only tab strip, shown only with two or more panes. Stacked sheets peek to the **right**, away from the resize divider; peek width is capped at three sheets (66px). Inactive editors are inert.
- All note editors autosave after 700ms and flush on blur; right-pane close also flushes and stays open if saving fails. Manual Save controls are removed; save failures retain the draft and offer retry. The full editor uses its owning entry form callback instead of the removed hard-coded form ID. Saved side-pane notes refresh a clean entry gallery without replacing its local edits.
- Verification fixtures run only in memory, separately from the owner's real library. Do not add placeholder notes to the real library for testing.

- Library entry **left-click always opens in the main area**, even while right panes exist. Only the explicit **Open in right pane** context-menu action creates/focuses a right pane. Each pane has an opaque, high-contrast 44px close button over its artwork, with a label distinguishing the entry/note and its title. Closing the final pane restores the full main width.
- Compact side-entry editors use one scrolling form. Notes follows the entry controls with a 24px gap, has no nested gallery scrollbar, and uses readable theme-aware headings, cards, and fixed-size arrow icons.
